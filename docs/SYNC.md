# 数据存储与同步

## 默认存储

完整数据保存在当前库的插件目录 `data.json`，由 Obsidian 的 loadData/saveData API 管理。

| 文件或数据 | 位置 | 同步方式 |
| --- | --- | --- |
| 书架、进度、评分、短评、订阅、连接配置、待推送任务、日志 | `.obsidian/plugins/anilink/data.json` | 配置同步工具包含此文件 |
| 程序路径、下载目录、Token、下载器密码 | 同一 data.json | 同步时一并传输，需私人空间 |
| 逐字段版本记录 | 同一 data.json 的 records | 外部文件更新时合并书架、进度和评价 |
| 设备标识 | `%LOCALAPPDATA%/AniLink/<库路径摘要>.device.json` | 每个设备自行生成 |
| 视频与 XML | 用户配置的媒体目录 | 自行备份和传输 |
| 网页登录会话 | Electron 会话 | 新设备可能需要重新登录 |

复制插件文件夹时保留 data.json，即可复制完整状态。移动整个库也会携带数据。某些同步工具默认忽略隐藏配置目录，需要开启社区插件配置同步，或显式包含此文件。Git 工作流必须检查忽略规则。不要将个人 data.json 推送到公开仓库。

## 自动迁移

升级时先读取库内数据。如果是旧版 deviceStorage 标记，则读取旧系统目录 JSON 并保存为库内格式。旧文件保留，供恢复使用。迁移或解析失败会停止加载，避免把错误状态覆盖成空书架。迁移完成后以库内数据为准。

需要恢复时，先停用插件、备份当前 data.json，再使用自己的备份恢复。旧版系统 JSON 是迁移时的快照，后续操作不会继续写回该文件。

## 多设备同时修改

书架元数据、状态、观看进度、评分、短评采用已有逐字段版本记录合并。收到外部 data.json 更新后，插件保留本机尚未保存的字段修改再合并，并刷新本机待推送任务的内容。

订阅、程序路径、凭据和其他配置仍属于完整文件快照。外部更新后重新加载插件才会采用这些配置。多个设备同时改写完整快照时，云盘或 Git 仍可能产生冲突文件，需要保留备份并按同步工具处理。当前没有分布式事务、云传输服务或端到端加密。

可选跨设备功能通过 `AniLink-sync/<分组>/<设备ID>.json` 独立交换逐字段记录，有助于避免不同设备同时覆盖同一个进度文件。共享记录包含私密短评，不包含连接凭据、本机路径、下载执行配置和本地文件记录。需要用户自己的同步服务传输，分组名不构成访问控制。

从同一台电脑复制到另一台电脑后，检查程序路径、媒体目录和下载器地址。插件不会替同步工具复制视频或网页 Cookie。
