# 跨设备同步

## 哪些数据在哪里

| 数据 | 存储位置 | 是否共享 |
| --- | --- | --- |
| 书架、状态、分集进度、评分、短评、私密标记、弹幕 CID／偏移 | 本机 JSON；开启同步后另存共享文件 | 可选 |
| Token、密码、服务地址、播放器／下载路径、显示偏好 | `%LOCALAPPDATA%/AniLink/<库路径摘要>.json` | 否 |
| 订阅与执行开关、下载记录、文件关联、已清理资源排除、待推送队列、日志 | 同一本机 JSON | 否 |
| 视频、同名 XML | 配置的视频目录 | 插件不传输 |
| 迁移标记 | 库配置目录下 `plugins/anilink/data.json` | 可同步，无凭据 |

同步服务需要自行配置。插件不会把视频或账号凭据发给另一设备；共享文件包含私密评价，请只用自己的同步空间。

## 两台设备如何使用

1. 第一台进入“连接设置 → 跨设备”，开启同步并填写分组，例如 `my-bangumi`，保存后“立即合并”。
2. 在现有同步工具中包含库内 **`AniLink-sync/my-bangumi/`**；如果使用 Obsidian Sync，检查 JSON 等其他文件的同步设置。Git 同步需自行将该私人数据目录加入私人同步范围，公开代码仓库应忽略它。
3. 第二台安装插件，独立配置同一 Bangumi 账号 Token 和本机路径，开启同步并填写相同分组。文件到达后点“立即合并”，或等待默认 15 秒合并周期。
4. 第二台只接收书架与进度，不继承订阅执行。需要在那里下载时再选字幕组并启用，避免重复下载。
5. 离线时正常修改，文件传输恢复后自动合并。不需要每次启动重新全量导入 Bangumi 收藏。

## 如何解决冲突

- 每台设备写自己独立的 JSON；合并使用逻辑版本号与设备 ID，不依赖两台电脑的系统时间。
- 不同分集、不同字段分别合并：A 看第 1 集，B 看第 2 集，两项都保留。评分不会覆盖另一端的独立进度修改。
- “设为未看”是有版本的新操作，能传播到另一设备；不会简单取最大集数。
- 同字段完全并发修改采用确定性的版本／设备 ID 顺序，所有设备最终得到相同值；不是保留两份评价。重要评价建议在一台设备编辑后等待同步完成。
- 移出书架使用隐藏记录，旧文件不会把条目重新显示。接收进度不会清理本机视频，不会创建自动下载任务。
- Bangumi 写入由原操作设备的持久队列完成；接收设备不会为每次资料交换重复提交全部账号状态。原设备网络恢复后会重试。
- 损坏、正在传输或过大的共享文件跳过并记录，下个周期重试；不会因此清空本地记录。

共享文件必须最终送达才能收敛；这不是实时多人协作服务。同步工具产生的额外冲突副本不会自动当作正式设备文件导入。不要手改或提前删除设备文件；停用设备前等待其修改传到其他端。

## 旧版迁移与备份

首次升级自动读取原 `data.json`，先把完整数据原子写入库外本机文件，再把原文件改成无凭据标记。读取或写入失败会停止迁移，原文件保留。后续重载以本机数据为准，不被其他电脑的 `data.json` 覆盖。

在“连接设置 → 跨设备 → 打开本机数据目录”定位备份文件。移动库路径会改变文件名摘要：关闭插件后，把原文件复制到新库对应的本机文件位置，或重新配置并接收共享书架。卸载插件不自动删除本机备份或共享历史。

插件不清理第三方同步历史版本或旧备份；旧版 Token 可能仍在其中，需要自行检查。不要把本机 JSON 提交到 GitHub。跨设备功能的合并、字段隔离与运行时交换经过自动测试；尚未在两台物理电脑上验证云传输。
